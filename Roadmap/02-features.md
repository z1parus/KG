# 02. Функциональные требования

Разделены по фазам. MVP (фазы 1–3) — то, без чего нельзя запускаться.
Остальное — наращивается после.

## MVP (Фазы 1–3)

### F1. Каталог и меню
- F1.1 Список категорий блюд.
- F1.2 Список блюд в категории с фото, названием, ценой, коротким описанием.
- F1.3 Карточка блюда: фото, состав, вес, цена, опции (размер/добавки при наличии), аллергены.
- F1.4 Поиск по меню (по названию).
- F1.5 Блок «Популярное» / промо-баннеры на главном экране.
- F1.6 Бейдж «нет в наличии» (блюдо видно, но нельзя заказать).

### F2. Корзина
- F2.1 Добавление блюд в корзину, выбор количества.
- F2.2 Сохранение опций блюда в позиции корзины.
- F2.3 Изменение количества / удаление позиций.
- F2.4 Подсчёт итога (сумма позиций + стоимость доставки, если применимо).
- F2.5 Промокод (базово: один код на % или фиксированную скидку).
- F2.6 Минимальная сумма заказа (если есть) — блокировка оформления.

### F3. Оформление заказа
- F3.1 Способ получения: доставка / самовывоз.
- F3.2 Адрес доставки (текст + комментарий для курьера; карта — опционально в фазе 2).
- F3.3 Контакты: имя, телефон (без обязательной регистрации на MVP).
- F3.4 Время: «как можно быстрее» или «ко времени».
- F3.5 Комментарий к заказу.
- F3.6 Способ оплаты: наличными/картой курьеру на MVP; онлайн — фаза 5.
- F3.7 Подтверждение заказа → экран успеха с номером.

### F4. Ресторан (админ-панель, веб)
- F4.1 Лента входящих заказов в реальном времени.
- F4.2 Принять / отклонить заказ.
- F4.3 Смена статуса: принят → готовится → готов → в пути → доставлен (или «выдан» для самовывоза).
- F4.4 Простое редактирование меню: блюда, цены, наличие, категории.
- F4.5 Управление режимом работы (открыто/закрыто) — блокировка приёма заказов вне часов.

## Фаза 4 — Пользователи и удержание

### F5. Аккаунты
- F5.1 Регистрация по телефону (SMS-код) или email+пароль.
- F5.2 Авторизация, восстановление доступа.
- F5.3 Профиль: имя, телефон, адреса (несколько сохранённых).
- F5.4 История заказов.
- F5.5 Повтор заказа в один тап.
- F5.6 Редактирование профиля и адресов.

### F6. Статусы и уведомления
- F6.1 Экран «Мои заказы» с актуальными статусами.
- F6.2 Push-уведомления при смене статуса заказа (FCM).
- F6.3 Локальные уведомления для веба (опционально).

## Фаза 5 — Онлайн-оплата

### F7. Платежи
- F7.1 Интеграция эквайринга (ЮKassa / Tinkoff / CloudPayments / Stripe — по гео).
- F7.2 Выбор способа оплаты при оформлении.
- F7.3 Привязка карты (токенизация) для повторной оплаты.
- F7.4 Чеки по 54-ФЗ (через платёжного провайдера).
- F7.5 Возвраты (через админ-панель) — базовый сценарий.

## Фаза 6 — Релиз и рост

### F8. Релиз
- F8.1 Публикация в App Store / Google Play / веб-домен.
- F8.2 App-иконка, splash, скриншоты, описание, метаданные.
- F8.3 Crashlytics, аналитика (GA4 / Amplitude), логи.
- F8.4 Onboarding на первый запуск (2–3 экрана).

### F9. Рост и лояльность (после релиза)
- F9.1 Программа лояльности: баллы за заказ, пороги скидок.
- F9.2 Реферальная программа («пригласи друга»).
- F9.3 Персональные акции / push по сегментам.
- F9.4 Отзывы и рейтинги блюд.
- F9.5 Экран «Избранное».

## Нефункциональные требования (общие)

- **Производительность**: первый кадр меню ≤ 2.5 с на среднем устройстве; кэшировать изображения.
- **Офлайн-минимум**: корректное сообщение «нет соединения», кэш последнего меню.
- **Доступность**: поддержать крупный шрифт, контраст, семантика для скринридеров (минимум).
- **Локализация**: ru как основной; заложить i18n (Flutter `intl`) с первого дня.
- **Безопасность**: Firestore/Supabase Security Rules; валидация на клиенте и сервере; токены не в коде.
- **Аналитика**: события с первого дня (view_item, add_to_cart, begin_checkout, purchase).
