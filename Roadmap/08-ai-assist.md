# 08. Подсказки для работы с AI-ассистентом

Файл-шпаргалка: как формулировать задачи ИИ-помощнику, чтобы он был максимально полезен
именно в этом проекте. Необязательный документ.

## Общие правила

- Указывай **контекст**: это Flutter-проект заказа еды, Firebase (или Supabase), монорепо Melos,
  Riverpod, go_router, freezed.
- Проси **сначала план/набросок** для нетривиальных задач, потом — реализацию.
- Указывай **путь к файлу/пакету** (`packages/features/menu/...`) — снижает галлюцинации.
- Проси **тесты** вместе с кодом (unit для репозитория, widget-тест для экрана).
- Проси соблюдать **конвенции**: `dart format`, `flutter_lints`, без комментариев в коде,
  если не попросил иначе.

## Полезные шаблоны запросов

### Создать новую фичу
```
Создай фичу X в packages/features/X по архитектуре feature-first (см. Roadmap/04-architecture.md).
Нужны: domain/entity, data/dto, data/repository (Firestore), application/controller (Riverpod),
presentation/screen + widgets. Покрой тестами репозиторий и виджет экрана.
Используй freezed для модели. Без комментариев в коде.
```

### Спроектировать модель данных
```
Спроектируй коллекцию Firestore для X согласно схеме в Roadmap/05-data-model.md.
Добавь Security Rules и индексы. Объясни выбор полей и индексов.
```

### Написать Cloud Function
```
Напиши Cloud Function (TypeScript, 2nd gen) createOrder: валидирует orderDraft, считает total,
проверяет промокод и доступность блюд, записывает в orders, отправляет FCM-пуш ресторану.
Валдация — сервер, источник правды по сумме — сервер.
```

### Рефакторинг
```
Отрефактори файл <path> под конвенции проекта (Riverpod 2.x, freezed, без комментариев).
Сохрани поведение, добавь недостающие тесты.
```

### Дебаг
```
Симптом: ... Шаги воспроизведения: ... Окружение: Flutter <version>, target <web/android>.
Покажи вероятные причины по приоритету и предложи минимальные проверки.
```

## Что НЕ просить у ИИ

- Не генерировать секреты/ключи Firebase — это делается в `flutterfire configure`.
- Не писать логику подсчёта суммы заказа на клиенте (см. риски #4).
- Не править `firebase_options.dart` руками.
- Не вставлять токены/пароли в код или README.

## Чек-лист перед принятием кода от ИИ

- [ ] `flutter analyze` без ошибок/предупреждений.
- [ ] `dart format --set-exit-if-changed .` проходит.
- [ ] Тесты добавлены и зелёные (`flutter test`).
- [ ] Иммутабельные модели (freezed), нет мутаций в виджетах.
- [ ] Чувствительная логика (сумма, валидация) — на сервере.
- [ ] Нет хардкода env/ключей.
