# 06. Пофазный roadmap

Оценки условные, в неделях при стабильной работе 2–3 человек. Каждая фаза заканчивается
демонстрируемым результатом (definition of done).

## Фаза 0 — Подготовка (1 неделя)

**Цель**: рабочий «скелет» проекта, можно запускать `flutter run` и видеть пустой шаблон.

- [ ] Создать монорепо (`apps/customer_app`, `apps/admin_app`, `packages/*`, `melos.yaml`).
- [ ] Настроить Flutter-проекты (iOS/Android/Web), выбрать каналы stable.
- [ ] Создать 2 Firebase-проекта: `food-dev`, `food-prod`; `flutterfire configure` для каждого.
- [ ] Настроить `flutter_dotenv` + `--flavor` dev/prod.
- [ ] Базовая дизайн-система: цвета, типографика, базовые виджеты (кнопки, поля, карточки).
- [ ] `go_router` с пустыми экранами-заглушками (главное, меню, корзина, заказ, профиль, админ).
- [ ] Линтинг: `flutter_lints`, `dart format`, CI на GitHub Actions (`analyze`, `test`, `format --check`).
- [ ] README с инструкцией запуска.

**DoD**: `flutter run -t lib/main_dev.dart` поднимает приложение на web/Android/iOS с нижней навигацией
и пустыми экранами.

---

## Фаза 1 — Каталог меню (2–3 недели)

**Цель**: пользователь видит меню, может открыть карточку блюда.

- [ ] Модель данных `categories`, `menu` (freezed-классы + DTO).
- [ ] `MenuRepository` поверх Firestore (пагинация/кэш через `cached_network_image`).
- [ ] Главный экран: баннеры + категории + «популярное» + секции меню.
- [ ] Экран категории: список блюд с фото, названием, ценой, коротким описанием.
- [ ] Карточка блюда (детальный экран): фото, состав, вес, опции, цена, кнопка «В корзину».
- [ ] Поиск по названию (простой `where('name', '>=', ...)` + локальная фильтрация).
- [ ] Бейдж «нет в наличии».
- [ ] Seed-скрипт / админ-форма для наполнения меню (временно — через Firestore Console).
- [ ] Виджет-кит: `DishCard`, `CategoryChip`, `SectionHeader`, `PriceText`.
- [ ] Тесты: репозиторий (mock), экран меню (golden/базовый widget test).

**DoD**: пользователь может пройти по категориям, открыть карточку блюда, увидеть опции.

---

## Фаза 2 — Корзина и заказ (2–3 недели)

**Цель**: пользователь может оформить заказ (доставка/самовывоз, оплата курьеру).

- [ ] Глобальный `CartController` (Riverpod), персист в Hive (корзина не теряется при перезапуске).
- [ ] Экран корзины: позиции с опциями, изменение qty, удаление, промокод, итог.
- [ ] Экран оформления: способ получения, адрес (текст), контакты, время, комментарий, способ оплаты.
- [ ] Cloud Function `createOrder`: валидация, подсчёт суммы, проверка промокода, запись в `orders`,
      отправка FCM-пуша ресторану (триггер `onCreate`).
- [ ] Экран успеха заказа с номером.
- [ ] Минимальная сумма заказа (читается из Remote Config / `restaurants`).
- [ ] Тесты: `createOrder` (functions emulator), валидация промокода, сценарий «офлайн».

**DoD**: можно оформить заказ «доставка, оплата курьеру» и он появится в Firestore со статусом `new`.

---

## Фаза 3 — Админ-панель ресторана (2 недели)

**Цель**: ресторан видит и обрабатывает заказы в реальном времени.

- [ ] Flutter-web `admin_app`: логин (email/пароль, роль `admin` через custom claims).
- [ ] Лента заказов: realtime-подписка на `orders` со статусами `new/accepted/cooking`.
- [ ] Действия: принять → готовится → готов → в пути → доставлен / выдан (самовывоз) / отменён.
- [ ] Управление меню: список блюд, вкл/выкл `available`, редактирование цены/названия/фото.
- [ ] Управление режимом работы (`isOpen`) — блокировка приёма заказов вне часов (Cloud Function).
- [ ] Базовая статистика: заказы сегодня, выручка, средний чек.
- [ ] Security Rules: `isAdmin()` gate на запись `menu`, `categories`, `banners`.

**DoD**: ресторан может обрабатывать заказы с экрана; приём/отмена/статусы работают end-to-end.

---

## Фаза 4 — Аккаунты и удержание (2 недели)

**Цель**: пользователи имеют профиль, историю и повтор заказа; приходят push о статусах.

- [ ] Firebase Auth (phone/email), связывание анонимной сессии с постоянным аккаунтом.
- [ ] Экран профиля, управление адресами (несколько).
- [ ] Экран «Мои заказы» (история + активные).
- [ ] Повтор заказа в один тап (черновик на основе старого заказа, но с актуальными ценами).
- [ ] StreamProvider на текущий заказ → обновление статуса в реальном времени.
- [ ] FCM: push при смене статуса; deep-link на экран заказа; обработка foreground/background.
- [ ] Onboarding на первый запуск (2–3 экрана).

**DoD**: залогиненный пользователь видит историю, повторяет заказ, получает push при смене статуса.

---

## Фаза 5 — Онлайн-оплата (по потребности, ~2–3 недели)

- [ ] Выбор эквайринга (ЮKassa / Tinkoff / CloudPayments — РФ; Stripe — вне РФ).
- [ ] Интеграция SDK/виджета оплаты, токенизация карты.
- [ ] Cloud Function `payOrder`: создание платежа, вебхук-обработка, обновление `paymentStatus`.
- [ ] 54-ФЗ: передача чека через провайдера (ЮKassa/CloudPayments умеют).
- [ ] Возвраты (админ) — базовый сценарий через API провайдера.
- [ ] Edge-кейсы: неуспешная оплата, таймаут, повторная попытка.

**DoD**: можно оплатить заказ онлайн; статус заказа и чек приходят корректно.

---

## Фаза 6 — Релиз и рост (1–2 недели + далее)

- [ ] App Store / Google Play: метаданные, иконки, скриншоты, приватность.
- [ ] Веб-версия: деплой на Firebase Hosting, домен, SSL.
- [ ] Crashlytics + GA4-события (view_item, add_to_cart, begin_checkout, purchase).
- [ ] Performance Monitoring.
- [ ] Onboarding, пустые состояния, ошибки сети, fallback.
- [ ] Промо-материалы для локального рынка (соцсети, офлайн-материалы в ресторане).
- [ ] Сбор обратной связи (форма/почта в профиле).

**Дальше (backlog)**:
- Программа лояльности и баллы.
- Реферальная программа.
- Отзывы и рейтинги блюд.
- «Избранное».
- Карта выбора адреса (Яндекс/Google Maps).
- Зоны доставки с автоматическим расчётом стоимости по гео.
- Курьерское приложение (отдельный таргет/приложение).
- A/B-тесты (Firebase Remote Config + A/B Testing).
- Мультиязычность (ru/…).
- Мультитенантность (несколько ресторанов).
